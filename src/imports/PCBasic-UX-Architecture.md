# PCBasic 工业级打样在线平台 — 用户体验架构方案

> **ArchitectUX Agent** | 2026-06-16  
> **项目**: pcbasic.com 外贸PCB/PCBA打样平台 UX重构  
> **目标**: 消除用户体验断点，打造从下单到物流跟进的全链路流畅体验

---

## 一、现状诊断：UX断点分析

### 🔴 断点1：首页信息过载，决策路径不清

| 问题 | 影响 |
|------|------|
| 6个轮播横幅消息分散，核心价值主张被稀释 | 新用户3秒内无法理解"我能得到什么" |
| 页面内容层级超过20个区块 | 滚动疲劳，CTAs之间互相竞争 |
| Mega菜单50+链接 | 选择瘫痪，PCB新手找不到入口 |
| "Online Quote"和"Instant Quote"重复出现 | 认知混淆 |

**严重度**: 🔴 Critical — 直接影响首页转化率

---

### 🔴 断点2：报价→下单链路断裂

| 问题 | 影响 |
|------|------|
| 报价表单提交后需等待人工回复，非即时 | 失去价格透明度优势（vs JLCPCB即时报价） |
| 无动态价格计算器（Gerber解析→即时报价） | 用户必须在"提交表单等邮件"和"关闭页面"间选择 |
| 3个分Tab报价表单（PCB / PCBA / CNC），切换需重新填写 | 跨品类询价体验割裂 |
| 报价表单与member.pcbasic.com 分属不同子域 | 登录态无法传递，需重复认证 |

**严重度**: 🔴 Critical — 这是核心转化漏斗的最大缺口

---

### 🔴 断点3：支付-订单管理跨域体验割裂

| 问题 | 影响 |
|------|------|
| 主站(www) ↔ 会员中心(member) 子域跳转 | 页面重载，状态丢失，用户迷失 |
| 登录/注册弹窗同时存在于两个域 | 双重认证，session不同步 |
| 购物车(pcbasic.com/cart)与订单管理跨域 | 加购后跳转至member域，回退困难 |
| 无"继续浏览"或快速返回报价的导航 | 用户被锁在member域 |

**严重度**: 🟠 High — 支付环节的摩擦直接导致弃单

---

### 🟡 断点4：物流追踪信息断层

| 问题 | 影响 |
|------|------|
| 物流追踪依赖外部DHL链接跳转 | 离开平台，品牌体验中断 |
| 无实时进度可视化（PCB制造阶段） | 7步流程仅在首页展示一次，订单页缺失 |
| 缺少主动推送通知（邮件/WhatsApp/站内信） | 用户需主动查询，焦虑等待 |
| 无制造进度条（已切割→已钻孔→已电镀→已测试） | 工业打样特有的长周期无透明化 |

**严重度**: 🟠 High — 直接影响复购意愿

---

### 🟡 断点5：移动端体验缺失

| 问题 | 影响 |
|------|------|
| 报价表单在移动端未做专门适配 | 文件上传困难，填写体验差 |
| Mega菜单在小屏不可用 | 导航完全失效 |
| member子域无响应式设计 | 工程师无法用手机查订单状态 |

**严重度**: 🟡 Medium — 工业客户PC占比高，但移动查询是刚需

### 2.2 详细流程链路表

| 阶段 | 用户动作 | 系统响应 | 当前状态 | 建议状态 |
|------|---------|---------|---------|---------|
| **1.获客** | 搜索"PCB prototype"→点击着陆页 | SEO页面+价值主张展示 | ✅ 已有 | 需A/B测试落地页 |
| **2.报价** | 上传Gerber→获取即时报价 | Gerber解析→规格自动填充→价格计算 | ❌ 缺失 | 🔥 P0优先级 |
| **3.下单** | 确认规格→填写地址→提交订单 | 库存检查→交期估算→订单创建 | ⚠️ 人工 | 🔥 需自动化 |
| **4.支付** | 选择支付方式→完成支付 | 支付网关→订单状态更新→邮件确认 | ⚠️ 跨域 | 🔥 需统一域 |
| **5.制造** | 查看进度→接收更新 | 工位扫描→进度条更新→异常推送 | ❌ 缺失 | 🔥 P1优先级 |
| **6.物流** | 获取单号→追踪包裹→签收 | DHL API→内嵌追踪→签收触发 | ⚠️ 外链 | 需内嵌 |
| **7.售后** | 质检反馈→复购/推荐 | NPS调研→复购优惠→推荐链接 | ❌ 缺失 | P2优化 |

## 六、交互模式定义

### 6.1 全局交互规范

| 元素 | 行为 | 反馈 |
|------|------|------|
| **文件上传区** | 拖拽/点击上传，自动解析Gerber | 进度条→解析动画→即时报价 |
| **报价计算器** | 规格变更实时更新价格 | 价格数字滚动动画 |
| **添加到购物车** | 点击后购物车图标徽章+1 | 侧边滑入购物车预览 |
| **支付按钮** | 点击→支付弹窗（不跳转） | 加载状态→成功动画→跳转订单页 |
| **进度条** | 制造数据自动更新 | 工位扫描后推动进度 |
| **物流追踪** | 内嵌DHL API数据 | 时间线自动刷新 |
| **通知** | 关键节点主动推送 | Toast → 邮件 → WhatsApp |

## 七、技术架构建议

### 7.1 统一域策略

```
当前: www.pcbasic.com + member.pcbasic.com (两个独立应用)
建议: pcbasic.com (单一Next.js/Nuxt应用)

优势:
• 统一认证（JWT跨路由共享）
• 购物车状态持久化（无需跨域Cookie）
• SEO集中（所有流量归入主域）
• 移动端PWA支持
```

### 7.2 即时报价引擎架构

```
用户上传Gerber → 浏览器端解析（gerber-parser.js）
                    ↓
              提取规格参数（层数、尺寸、孔数、线宽）
                    ↓
              发送至后端 /api/quote/instant
                    ↓
              匹配价格矩阵 → 返回实时报价
                    ↓
              前端渲染价格 + 交期选项
```

### 7.3 制造进度追踪数据流

```
MES系统（制造执行系统）
    ↓ 工位扫描事件
WebSocket / Server-Sent Events
    ↓ 实时推送
用户订单详情页（进度条更新）
    ↓ 同时触发
• 站内通知（网页）
• 邮件通知
• WhatsApp通知
```
