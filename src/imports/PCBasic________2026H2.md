### 3.2 六大策略详解

#### 策略一：报价提速——"30 秒看价"

> **目标**：消除"等报价"这一转化率杀手，对标 JLCPCB 的即时报价体验

| 举措 | 描述 | 预期效果 |
|------|------|---------|
| **自动报价引擎** | 基于规则引擎（层数/尺寸/数量/工艺/交期），实现 PCB 参数选择后即时显示价格 | 报价等待时间从 2-24h → <5s |
| **智能报价引导** | 用 1-2 个简单问题引导用户（"您需要裸板还是组装板？"）到正确表单 | 减少用户迷失，提升入口转化 |
| **高级选项折叠面板** | 铜厚、表面处理、阻焊颜色等高级参数放入可折叠区域 | 满足专业用户同时不吓跑新手 |
| **报价对比展示** | 同时展示标准交期价和加急价，让用户自主权衡 | 提升加急订单比例 |

#### 策略二：体验升级——"3 分钟下单"

> **目标**：从文件上传到支付完成，核心路径控制在 3 分钟内

| 举措 | 描述 | 预期效果 |
|------|------|---------|
| **Gerber 拖拽上传 + 格式校验** | 支持拖拽上传、自动识别格式、上传进度条、格式错误即时提示 | 减少文件相关问题导致的中断 |
| **在线 Gerber 预览** | 上传后自动解析并展示 2D/3D 预览，标注关键参数 | 降低设计错误率，减少返工 |
| **下单步骤可视化** | 清晰的进度指示器（上传 → 审核 → 支付 → 生产 → 发货） | 降低用户焦虑，提升完成率 |
| **新用户 Onboarding** | 首次下单时提供 3-5 步 Tooltip 引导 | 新用户首次下单完成率提升 |
| **支付透明化** | 在支付页面明确展示所有支付方式、币种、手续费 | 减少支付环节犹豫 |

#### 策略三：留存闭环——"老客价值最大化"

> **目标**：从"一锤子买卖"到"长期合作制造伙伴"

| 举措 | 描述 | 预期效果 |
|------|------|---------|
| **一键复购（Reorder）** | 历史订单页增加 Reorder 按钮，自动填充所有参数和文件 | 返单操作时间从 30min → 2min |
| **报价历史 & 文件库** | 用户中心增加报价历史查询、Gerber/BOM 文件云端管理 | 减少重复操作，提升便利性 |
| **订单状态多渠道推送** | 邮件 + 站内信 + 微信模板消息，关键节点主动通知 | 减少用户主动查询，提升满意度 |
| **发票在线下载** | 订单完成后自动生成电子发票，支持在线下载 | 减少客服工作量，提升企业客户体验 |
| **优惠券 & 积分体系** | 下单返积分、复购优惠券、新用户首单优惠 | 提升复购率和客单价 |

#### 策略四：架构重塑——"清晰直达"

> **目标**：让用户 3 秒内找到想去的地方，让搜索引擎正确理解网站内容

**核心问题诊断**：

```
当前架构问题：
├── 导航层级混乱：PCB 产品线 10+ 类型平铺在导航中，用户不知从何下手
├── 页面跳跃体验断裂：member.pcbasic.com 与 www.pcbasic.com 域名不同，体验割裂
├── 内容孤岛：博客/知识库与产品页无关联，无法互相引流
├── SEO 基础薄弱：大量页面 Title/Description 重复，结构化数据缺失
├── URL 结构不规范：中英混用、层级过深、无语义化
└── 首页信息过载：Hero区 + 3个报价表单 + 客户滚动条 + 数据统计 + 合作品牌 + 产品列表……全堆一屏
```

| 举措 | 描述 | 预期效果 |
|------|------|---------|
| **信息架构重构** | 按用户任务（"我要打样/批量/组装/机加工"）而非产品类型组织导航 | 降低认知负荷，提升导航效率 |

#### 策略六：满意度跃迁——"从没投诉到超出预期"

**当前满意度管理差距**：

```

      ↓ 问题在哪？
      ├── "满意率 99.6%" 怎么来的？—— 可能只是"没投诉的人 = 满意"
      ├── 没有主动收集满意度的机制（NPS、CSAT、CES）
      ├── 没有满意度数据的分析闭环（收到→分析→行动→验证）
      ├── 没有让满意客户发声的渠道（评价、推荐、案例）
```

## 五、指标体系：怎么衡量成功？

### 5.1 北极星指标

```
北极星指标 = 月活跃付费用户数（Monthly Active Paying Users, MAPU）
```

> 选择理由：PCBasic 的核心挑战不是"有没有人来"，而是"来了之后下不下单、下完单回不回来"。MAPU 综合反映了获客、转化、留存三个链路的健康度。

### 5.2 驱动指标（L1）

### 7.3 前端框架选型

#### 核心推荐：**Next.js 15（App Router）**

| 维度 | Next.js 15 | Nuxt 3 | Remix | 传统 SPA (React/Vue) |
|------|-----------|--------|-------|---------------------|
| SSR/SSG 支持 | ✅ 完整 | ✅ 完整 | ✅ 完整 | ❌ 无（SEO 弱） |
| SEO 友好度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐ |
| React Server Components | ✅ | ❌（Vue） | ❌ | ❌ |
| 社区生态 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| 国际化支持 | ✅ 内置 | ✅ 内置 | 第三方 | 第三方 |
| Vercel/云部署 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| 学习成本 | 中 | 低 | 中 | 低 |
| **推荐** | **✅ 首选** | 备选（Vue 团队） | 不推荐 | ❌ 排除 |

**选择 Next.js 的核心理由**：

1. **SEO 是战略需求**：有机搜索目标占比 ≥35%，SSR 是前提条件，纯 SPA 直接排除
2. **React Server Components（RSC）**：报价页、产品页等重内容页无 JS 可以大幅提升 LCP
3. **App Router 的并行路由**：报价页"参数面板 + 结果卡片"天然适合并行 Streaming
4. **生态最大**：Gerber 解析、3D 预览等第三方组件几乎都有 React 版本
5. **增量迁移友好**：可以从旧站逐页接管，不需要一次性重写

**UI 组件方案**：

```
选型：Tailwind CSS + shadcn/ui + Radix UI primitives

理由：
├── Tailwind：原子化 CSS，Design Token 集成自然，改色只改变量
├── shadcn/ui：组件源码拥有，可完全按品牌红定制，无 vendor lock-in
└── Radix UI：无障碍基础（a11y）完整，键盘导航/屏幕阅读器开箱即用

❌ 不选：Ant Design / MUI（主题定制成本高，包体积大，与品牌红适配性差）
```

| 维度 | 单体应用 | 微服务 |
|------|---------|--------|

### 7.5 报价引擎技术方案

> 即时报价是整个产品提升规划的 P0 核心，需要独立设计其技术方案。

```
报价引擎架构：

┌─────────────────────────────────────────────────────────┐
│                   规则引擎层                              │
│                                                         │
│  输入参数                                                │
│  ├── 板层数（1/2/4/6/8层）                               │
│  ├── 板材尺寸（mm × mm）                                 │
│  ├── 数量（5/10/20/50/100/...）                          │
│  ├── 板材（FR4 / 铝基 / 高频板）                          │
│  ├── 铜厚（1/2/3oz）                                    │
│  ├── 表面处理（HASL / ENIG / OSP）                       │
│  ├── 阻焊颜色（绿/红/蓝/黑/白）                           │
│  └── 交期（3天/5天/7天/加急）                             │
│                                                         │
│  定价逻辑                                                │
│  ├── 基础价 = f(层数, 尺寸, 数量)                         │
│  ├── 工艺附加价 = 铜厚溢价 + 表面处理溢价 + 颜色溢价        │
│  ├── 交期系数 = 标准(1.0) / 加急(1.3-1.8)               │
│  └── 最终价 = (基础价 + 工艺价) × 交期系数 × 汇率          │
│                                                         │
│  缓存策略                                                │
│  └── Redis 缓存常用参数组合报价（TTL: 1h）                │
│      命中率预期 >80%（常见规格集中）                       │
└─────────────────────────────────────────────────────────┘
```

**技术选型**：

| 方案 | 实现方式 | 优缺点 |
|------|---------|--------|
| **规则引擎（推荐）** | Python FastAPI + JSON 规则配置 | 非技术人员可维护规则，灵活改价 |
| 公式驱动 | 代码写死数学公式 | 简单快，但改价需发版 |
| 机器学习定价 | ML 模型预测 | 高复杂度，初期数据不足 |
| 第三方 CPQ 工具 | Salesforce CPQ 等 | 成本高，过度依赖外部系统 |

**关键约束**：
- 报价响应时间 < **200ms**（Redis 缓存命中）< **500ms**（实时计算）
- 准确率 ≥ 95%（与最终成交价偏差在 ±5% 以内）
- 非标参数（HDI、厚铜、埋盲孔）仍走人工报价，引擎不覆盖

### 7.7 数据库选型

| 数据库 | 用途 | 选型理由 |
|--------|------|---------|
| **PostgreSQL** | 主业务数据库（用户/订单/报价/BOM） | 关系型+JSON支持，事务可靠，成熟稳定 |
| **Redis** | 缓存（报价缓存/会话/限流/队列） | 高性能，Pub/Sub 支持通知场景 |
| **Elasticsearch** | 全文搜索（产品/文档/订单搜索） | 多语言分词，PCB 参数结构化搜索 |
| **ClickHouse** | 分析/数据仓库（行为埋点/报表） | 列式存储，适合大量事件日志聚合查询 |
| **S3/COS 对象存储** | Gerber 文件/BOM/发票/图片存储 | 成本低，全球 CDN 分发，持久化 |

**重要约束**：
- Gerber 文件**不存入数据库**——存入对象存储，数据库仅保存文件路径和元数据
- 用户 Gerber 文件加密存储（AES-256），只有本人可下载，生产完成 90 天后提示用户确认是否保留

| 指标 | 当前（估） | 目标 | 优化措施 |

### 7.11 技术迁移策略

> **原则**：不停机、不 Big Bang 重写、分批灰度、SEO 不损失

```
迁移分三阶段（对应产品路线图时间线）：

Phase 1（7-8 月）：新架构起步
├── 搭建 Next.js 新项目，建立 Design Token + 组件库
├── 新功能（报价引擎、首页改版）全部在新架构开发
├── 旧页面用 Next.js rewrites 代理，用户无感知
└── 部署：先上 Staging，验证性能数据后推 Production

Phase 2（9-10 月）：核心页面迁移
├── 产品页、下单页、用户中心迁移到 Next.js（流量最大的页面）
├── 旧 URL 全部 301 重定向到新 URL（SEO 保持）
├── A/B 测试：新旧页面对比转化率，确认提升后全量切换
└── 旧服务逐步下线

Phase 3（11-12 月）：服务架构优化
├── 报价引擎服务独立部署（容器化，按需弹性扩缩）
├── Gerber 解析服务独立化
├── 监控体系完善（Grafana 看板上线）
└── 性能基准测试，确保 Core Web Vitals 全面达标
```

**SEO 保护措施**：

| 风险 | 保护措施 |
|------|---------|
| URL 变更导致排名下降 | 所有旧 URL 配置 301 永久重定向，Google Search Console 密切监控 |
| 迁移期间页面不可访问 | 旧服务先保留 30 天，确认新服务正常后再下线 |
| 内容索引延迟 | 手动提交 Sitemap 到 GSC，触发重新抓取 |
| 动态内容 SEO 丢失 | 确保所有产品页、行业页均为 SSR 渲染（非 CSR） |

## 九、Non-Goals（明确不做什么）

| 不做 | 原因 |
|------|------|
| ❌ 自研 PCB 设计工具（类 EasyEDA） | 投入巨大且非核心，应通过 API 对接已有工具 |
| ❌ 元器件商城（类立创商城） | 供应链复杂度极高，短期 ROI 不划算 |
| ❌ 全品类即时报价（CNC/3D 打印） | 非标品类占比低，人工报价可接受 |
| ❌ 大规模品牌广告投放 | 产品体验未达标前投放是浪费流量 |
| ❌ 桌面客户端/插件 | Web 优先，移动端做小程序而非原生 App |
| 🆕 ❌ 全站改版一刀切上线 | 风险太大，必须分批迁移 + 灰度发布 |
| 🆕 ❌ 虚假评价/刷分 | 严重损害品牌信誉，违反平台规则，绝对禁止 |
| 🆕 ❌ NPS 调研过度打扰 | 同一用户 90 天内最多触发 1 次 NPS，CSAT 限制 1 次/订单 |
| 🆕 ❌ 技术架构一次性全量重写 | 停机风险高、工期长、SEO 损失难控制，必须增量迁移 |
| 🆕 ❌ 自研 Gerber EDA 内核 | KiCad/KiCanvas 已有成熟方案，不重复造轮子 |
| 🆕 ❌ Phase 1 上微服务完整架构 | 团队规模不支持，先混合架构验证业务，Q4 再拆 |
